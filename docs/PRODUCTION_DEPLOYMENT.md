# Production deployment (candidate, not certified)

The independent Compose file does not inherit development source mounts, ports or reload. Verify .gitignore covers .env.production and all populated secret files. Never copy production secrets into an image or VITE variables.

1. Provision a Linux Docker host, a real DNS name, firewall (80/443 and restricted SSH), and persistent storage. Select an AI provider and model; for Ollama configure a reachable private endpoint, not the example ollama hostname (no Ollama service is included). Confirm provider egress and privacy policy.
2. Create .env.production from example, set a unique DB password and matching URL-encoded DSN; set OAuth credentials and Fernet key. Preserve the key across deployments, store separately with access control. Create a separate GitHub OAuth app with https://<domain>/api/v1/auth/github/callback. Do not rotate an existing encryption key without a migration plan.
3. Run `docker compose -p ita-prod --env-file .env.production -f docker-compose.prod.yml config --quiet`, then `build`, then `up -d`, then `ps -a` (same prefix). Migration must exit 0. Back up DB before any upgrade. Tag immutable images with release SHA and pin base-image versions/digests after verification.
4. Check HTTPS /, /api/v1/health, /api/v1/auth/github/status, Swagger disabled, OAuth, real RQ job, scanner PONG, AI inference and Dashboard. Caddy container health only checks config syntax; external HTTPS probes are mandatory. ClamAV readiness must be tested separately (signature download and scanner ping). Use external monitoring for queue age, job failures, error rate, latency, disk, certificate expiration and backups.
5. Backup PostgreSQL with `pg_dump -Fc` to a file inside the container then `docker compose ... cp postgres:/tmp/backup.dump ./backup.dump` (avoids binary PowerShell 5.1 redirection), remove temporary copy after checking. Encrypt backups, move off-host, define retention/RPO/RTO, and perform `pg_restore` to a disposable database. Preserve encryption key independently; assess Redis queue recovery and persistent application files. Never use down -v on production.
6. Review logs locally without publishing tokens or private code; log rotation in Compose limits local disk, not centralized monitoring. Configure alerts and access controls. Scan dependencies/images; run staging tests before go-live. Do not assume production readiness merely because containers are Up.

No Docker daemon or real domain was available when preparing this candidate. Test all builds, runtime filesystem paths, migration, scanner, Caddy TLS and AI provider configuration on staging before deployment. The production config intentionally does not start Ollama, and its hostname must be replaced with a private reachable service when that provider is selected. Dev Compose unchanged.
